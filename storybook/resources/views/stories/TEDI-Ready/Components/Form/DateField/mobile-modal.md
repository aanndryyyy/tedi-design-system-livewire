`[modal]="true"` opens the calendar in a modal with Cancel/Confirm. The first field uses the compact centered layout; the second combines `[fullscreen]="true"` with `[calendarFullWidth]="true"` to spread the calendar across the fullscreen modal. Both `modal` and `fullscreen` accept `true | false | sm | md | lg | xl`.

> **Port notes.** `modal` is ported: `true`, `false`, or a breakpoint name resolved in the browser by `tediDateField`. `calendar-full-width` is ported. **`fullscreen` is accepted but has no effect**: upstream's fullscreen styles target the `ModalService` dialog pane, and this package's modal only has the standalone branch, which has no fullscreen rule. So the second field opens a regular centered modal with a full-width calendar.
>
> The modal renders under the same server-side `open` prop as the popover, so toggle the `centeredOpen` / `fullscreenOpen` controls to see it. The calendar inside it shows `draft`, falling back to `value`. Confirm dispatches a bubbling `tedi-date-field-confirm` event: commit `draft` and set `open` to false. Cancel, the close button, the backdrop and Escape dispatch `tedi-modal-close`: discard `draft` and set `open` to false. In Livewire, bind them on the field with `wire:tedi-date-field-confirm="…"` and `wire:tedi-modal-close="…"`.
